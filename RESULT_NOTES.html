결과 설명자료

「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 제출작 혼디봅서예 (처음 가는 데이터센터, 걱정 대신 기대로)

이 문서는 문제 정의, Agent 구조, 주요 기능, 실행 결과, 검증 방법과 한계, 센터 활용 방안을 차례로 적습니다. 설치와 사용법은 README.md, 데이터 내역은 DATA_USE.md 에 있습니다.

1. 문제 정의

1-1. 누구의 어떤 문제인가

이 대회의 취지는 "IT 비전문가인 도민도 제주빅데이터센터에서 직접 실행하고 활용할 수 있도록" 하는 것입니다. 그런데 처음 가는 사람을 막는 것은 분석 실력보다 먼저 모른다는 불안입니다.

불안실제 사정확인한 곳
"내가 쓸 만한 데이터가 있긴 할까?"센터의 데이터 검색 화면은 센터 안에서만 열립니다. 밖에서는 엑셀 명세서를 내려받아 읽어야 합니다센터 담당자 통화(2026-11-19), 데이터 명세서 v13
"가서 뭘 어떻게 해야 하지?"예약은 하루 단위, 데이터는 한 달씩 내려받기, 가져올 자료는 CSV만. 규칙이 이용가이드, 공지, 문의 답변에 흩어져 있습니다제주데이터허브 이용가이드, 대회 게시판 운영 답변, 통화
"AI한테 시키면 안 되나?"센터 PC는 밖으로 올리기가 막혀 있고 이용 기록을 확인합니다. 센터 데이터를 외부 AI 서비스에 넣어 분석할 수 없습니다통화, 운영 답변
"결과를 가져갈 수는 있나?"반출은 시스템으로 신청하고 담당자가 파일을 모두 열어 검수합니다. 10 미만 숫자, 역산, 활용 사유를 봅니다제주빅데이터센터 데이터 반출 정책(2026-09-01 개정), 통화
"하루에 못 끝내면?"다른 날로 늘리는 것은 자리가 비어 있을 때만 됩니다통화

대회 게시판 운영 답변에 따르면 지금의 방문자는 "대다수 … 기관과 기업이며, 논문이나 현황자료 작성, 사업계획서 작성이 대부분"입니다. 즉 방문의 목적은 문서이고, 필요한 것은 문서에 쓸 문장과 표, 그리고 그 근거입니다.

1-2. 풀려는 것

처음 가는 사람이 센터 데이터로 문서에 쓸 문장과 표를 얻기까지를, 가기 전부터 결과를 기다리는 동안까지 네 장면으로 돕습니다.

장면돕는 일
① 가기 전에(집에서)센터 데이터 71종의 이름과 칸 설명을 둘러보고, 쓰려는 문서에 맞는 자료를 추천받고, 센터 이용 규칙을 미리 읽습니다
② 센터에서내려받은 CSV를 그대로 넣으면 어떤 표인지 알아보고, 실제 양식을 본뜬 초안을 채우고, 쓰려는 문장을 자료로 검산합니다
③ 가져갈 때10 미만 값과 되살릴 수 있는 합계를 가리고, 담당자가 먼저 볼 '반출 신청용 점검 요약'을 붙입니다
④ 기다리는 동안결과가 언제 어떻게 오는지 알려 줍니다

약속하지 않는 것: 반출 승인(센터가 정합니다), 예측과 원인 분석, 업종 전체 매출의 단정(비씨카드 한 곳의 자료입니다).

2. Agent 구조

2-1. 한 바퀴

이용자의 말
  → ① 이해      문서 종류, 업종, 지역, 기간, 대상, 주장의 방향을 읽는다
  → ② 자료 확인  넣은 표의 종류, 있는 달, 지역 칸을 본다 (모자라면 여기서 끝: 받을 표와 달을 말한다)
  → ③ 계획      요약, 대상 비교, 전년 같은 달 대비, 순위, 문서 틀, 자료 추천 가운데 고른다
  → ④ 계산      정해진 규칙으로 합계와 비율을 낸다
  → ⑤ 사전 점검  센터 표면 10 미만과 역산될 값을 가린다
  → ⑥ 판정      써도 됩니다 / 이렇게 고쳐 쓰세요 / 이 자료로는 쓸 수 없습니다
  → ⑦ 작성      문장, 근거 표, 계산식, 출처 문구, 다음에 해 볼 일

걸음마다 '무엇을 정했고 왜 그랬는지'를 남기고, 화면의 '어떻게 확인했나요'에서 펼쳐 볼 수 있습니다.

2-2. AI의 역할과 '외부 모델 없음'이 기본인 이유

대회 게시판 운영 답변은 센터의 반출 불가 데이터 원본이나 조회 결과를 외부 LLM API로 보내는 것은 어렵고, 질문 문장에 센터 값을 적어 보내면 "해당 값 역시 외부로 전송되는 데이터로 볼 수 있습니다"라고 했습니다. 통화로 확인한 분석실 조건도 같습니다(밖으로 올리기 차단, 이용 기록 확인). 외부 모델에 기대는 에이전트는 센터 파일이 들어온 순간 핵심 기능을 쓸 수 없습니다.

그래서 에이전트의 판단(말을 일로 바꾸기, 자료가 답할 수 있는지 보기, 계산 고르기, 판정, 답의 근거를 스스로 검사하기)을 PC 안의 규칙과 계산으로 구현했습니다. 이 제출물은 외부로 아무것도 보내지 않고, 운영 비용이 들지 않으며, 같은 입력에 늘 같은 답을 냅니다.

외부 AI API: 부르지 않습니다. 규칙으로 읽지 못한 자유로운 문장을 언어 모델로 다시 쓰는 층은 설계만 해 두고 이번 제출물에는 넣지 않았습니다. 센터가 외부 전송 기준을 정하면 붙일 수 있는 자리(문장 이해 앞, 사전 점검을 통과한 결과 뒤)만 남겨 두었습니다.

2-3. 구성 파일

파일하는 일
evm/understand.py규칙 기반 문장 이해(업종·지역·대상·방향 사전과 순서 규칙)
evm/store.py, evm/catalog.pyCSV 읽기, 머리글로 표 종류 알아보기, 메모리 보관
evm/calc.py계산 규칙(합계, 구성, 비교, 전년 대비, 순위, 반출 사전 점검). 숫자는 여기서만 나옵니다
evm/agent.py한 바퀴(이해 → 자료 확인 → 계획 → 계산 → 점검 → 판정 → 작성)
evm/narrate.py문장 틀과 숫자 검사(문장 속 숫자가 계산 결과에 있는지)
evm/docflow.py문서 틀(사업계획서 시장·고객 현황, 월간 소비동향, 자료 요약), 범용 요약, 받을 자료 추천
evm/identity.py다섯 원칙과 이름
evm/server.py, evm/report.py, web/이 PC 안에서만 응답하는 웹 서버, 답 카드와 인쇄용 쪽, 화면
evm/evalrun.py정답표 검증
inputs/*.json센터 이용 안내, 데이터 목록, 추천 규칙, 틀, 이름(코드를 고치지 않고 바꿀 수 있는 설정)

프롬프트: 이 제출물에는 언어 모델이 없으므로 프롬프트가 없습니다. 그 자리를 evm/understand.py 의 낱말 사전·순서 규칙과 evm/narrate.py 의 문장 틀이 대신합니다.

2-4. 다섯 원칙과 지키는 장치

화면에 적힌 원칙코드의 장치
근거 없이 숫자를 말하지 않습니다문장 속 숫자가 계산 결과(와 기간, 고정 기준값)에 있는 값인지 검사하고, 아니면 그 문장을 버립니다
먼저 자료를 확인하고 말합니다계산 전에 표 종류, 달, 지역 칸을 확인합니다
이 자료로 알 수 없는 것은 모른다고 합니다예측, 원인, 전체 매출, 점포 수 질문은 숫자 없이 이유를 답합니다
틀린 문장은 바로잡습니다판정이 '고쳐 쓰기'면 "아니요,"로 시작하고 실제 순서나 방향으로 다시 씁니다
가려야 할 숫자는 가립니다10 미만 값과 합계·비중을 함께 가립니다

3. 주요 기능

걸음이용자가 하는 일에이전트가 하는 일
데이터 둘러보기(집에서도)검색하거나 분야를 골라 훑어보고 '받을 목록에 담기'센터 데이터 71종의 설명, 칸 이름(한글·영문), 예시, 반출 조건, 많이 찾는 데이터를 보여 줍니다
센터 이용 안내'센터 이용 안내'를 엽니다방문 전부터 퇴실 뒤까지 여섯 단계의 센터 규칙을 항목마다 출처와 함께 보여 주고, 확인하지 못한 것은 따로 적습니다
받을 자료 추천'처음 오셨나요?'에서 고르거나 말로 묻습니다센터의 어떤 표를 어떤 조건으로 받을지 추천하고 '자료 받는 법'을 붙입니다
CSV 넣기내려받은 파일을 그대로 넣습니다머리글로 어떤 표인지 알아보고 기간과 행 수를 보여 줍니다. 모르는 표는 범용 요약만 하고, 반출 사전 점검을 하지 않는다고 알립니다
틀 고르기와 초안틀을 고르고 업종이나 달을 넣습니다자료 진단을 먼저 보이고, 실제 양식을 본뜬 틀의 칸대로 문단과 표를 채웁니다. 못 채우는 칸은 이유와 필요한 자료를 말합니다
문장 검산쓰려는 문장을 그대로 넣습니다판정(써도 됩니다 / 이렇게 고쳐 쓰세요 / 이 자료로는 쓸 수 없습니다), 두 값과 차이, 고쳐 쓸 문장, 근거 한 장. 낱말이 모호하면 되묻습니다
반출 신청 전 점검'PDF로 저장'해 센터 시스템에 직접 신청합니다10 미만 값과 되살릴 수 있는 합계를 가리고 '반출 신청용 점검 요약'과 신청 설명 초안을 만듭니다
복사와 퇴실 정리칸마다 '복사', 끝나면 '퇴실 정리'표는 탭으로 나눠 복사합니다(엑셀에는 칸대로, 한글·워드에서는 '표로 변환'). 퇴실 정리는 프로그램 안의 파일과 결과를 모두 지웁니다

5-3. 한계

한계화면과 문서에서의 표시, 그리고 대비
비씨카드 결제분만의 자료카드 자료의 숫자 답마다 한계 문장을 붙입니다
카드 밖의 표는 사전 점검을 하지 않음범용 요약에 "반출 사전 점검이 적용되지 않습니다"를 붙여, 그 요약을 그대로 반출 신청에 쓰지 않도록 알립니다
실제 센터 CSV를 보지 못함공개 명세서와 운영 답변에 맞춘 가상 파일로 시험했습니다. 머리글이 다르면 범용 요약으로 넘어가며 멈추지 않습니다. 실제 파일에서의 동작은 확인되지 않았습니다
공개 데이터는 2025년 6월까지그 뒤의 달을 물으면 센터에서 받을 표와 달을 안내합니다
이용자 수는 서로 다른 사람의 수가 아님이용자 수를 쓰는 답에 알림을 붙입니다
요일·시간대 공개 자료는 업종 구분이 없음"제주 전체 값이며 이 업종만의 값이 아닙니다"라고 적습니다
반출 사전 점검은 심사를 대신하지 못함'반출 신청 전 점검'이라고만 부르고, 승인 여부는 센터가 정한다고 적습니다
규칙 기반 이해의 한계사전에 없는 표현은 되묻거나 예시 문장을 제안합니다. 지어내서 답하지 않습니다
카드 밖 데이터의 전용 틀 없음외식업 포스, 버스, 유동인구 등은 받을 자료 추천, 틀의 얼개, 범용 요약까지만 됩니다
센터 이용 안내의 기준일2026-11-19에 확인한 내용입니다. 항목마다 출처를 붙였고, 확인하지 못한 것은 '센터에 확인 필요'로 따로 적었습니다. 현장 안내가 다르면 센터 안내가 맞습니다
Windows PC에서의 실행 미확인개발과 확인은 macOS에서 했습니다. 실행 파일은 Windows 규칙에 맞춰 만들었고 코드는 운영체제에 따라 달라지는 부분이 없게 썼지만, Windows 11 실기 확인은 하지 못했습니다. 문제가 생기면 README 6절을 봐 주세요

6. 센터 활용 방안

  • 방문 전 판과 센터 판이 같은 프로그램입니다. 집 PC에서는 묶음에 든 공개 데이터와 공개 명세서만으로 둘러보기·추천·안내·공개 데이터 초안이 되고, 센터 PC에서는 내려받은 CSV를 넣어 읍면동 단위까지 이어집니다. 대회 게시판 운영 답변은 같은 Agent를 개인 PC에서 따로 실행하는 것이 가능하다고 했습니다. 다만 공개 원본 데이터의 재배포는 제한되므로, 방문 전 판을 어떻게 나눠 줄지는 센터와 협의해야 합니다(데이터 없이 둘러보기와 안내만 담을 수 있습니다).
  • 탑재 절차는 세 걸음입니다. ① Python 3.12 이상 설치 ② 압축 풀기 ③ run.bat 바로가기. 추가 패키지, 외부 서버, 모델 파일, 이용료가 없습니다.
  • 안내데스크의 반복 질문을 덜어 줍니다. "어떤 데이터를 받아야 하나요", "여러 달은 어떻게 받나요", "반출은 어떻게 신청하나요"를 화면이 먼저 답합니다.
  • 검수하는 담당자가 보기 편한 신청물을 만듭니다. 인쇄물 맨 위에 원본 데이터, 가공 방법, 실린 수치, 10 미만 처리, 역산 점검, 활용 목적이 한 표로 옵니다.
  • 센터가 직접 고칠 수 있습니다. 센터 규칙(inputs/center_guide.json), 데이터 목록(inputs/center_catalog.json), 추천과 틀(inputs/report_catalog.json, inputs/doc_templates.json), 이름(inputs/branding.json)은 설정 파일이라 문장과 목록은 코드를 고치지 않고 바꿀 수 있습니다(계산식과 점검 기준을 바꿀 때는 코드 수정이 필요합니다).
  • 퇴실 규칙에 맞습니다. '퇴실 정리' 단추가 프로그램 안의 파일과 결과를 지우고, 프로그램이 스스로 저장하는 것은 없습니다(직접 저장한 PDF와 따로 연 인쇄 탭은 이용자가 정리합니다).

다음에 더할 것: 가장 많이 찾는 (시간대)·(요일별)_v02 전용 틀, 외식업 포스·버스·유동인구 묶음의 전용 틀, 실제 센터 CSV로의 검증, 센터가 기준을 정하면 사전 점검을 통과한 결과에만 외부 모델을 붙이는 문장 다듬기.
